# Контекст проекта «Игра-мозаика»

Краткая справка для следующих сессий. Техническое задание — [`prompts/INITIAL.md`](../prompts/INITIAL.md).

## О проекте

Браузерный пазл из квадратных фрагментов. Три экрана в одном документе: галерея картинок → выбор сложности → игровое поле. Состояние живёт только в памяти (плюс выбранный язык в `localStorage`).

## Стек

- Ванильный JavaScript (ES2015+) и CSS3, без сборщика, компиляции и зависимостей.
- Точка входа — `docs/index.html`, пути к скриптам и стилям относительные (`./css/...`, `./js/...`).
- Чистый фронтенд-SPA: бэкенда и БД нет. Картинки — внешние URL из фиксированного массива.
- Скрипты подключены обычными `<script>` (не модулями), чтобы страница открывалась и по `file://`. Порядок важен: `images.js → i18n.js → grid.js → game.js → app.js`.

## Файлы

| Файл | Ответственность |
|---|---|
| `docs/js/images.js` | массив `IMAGES` (менять нельзя — задан в ТЗ), кэш натуральных размеров, `loadImageSize()` |
| `docs/js/i18n.js` | словарь `STRINGS`, `detectLang()`, `t()`, `setLang()`, `applyTranslations()` по `data-i18n` |
| `docs/js/grid.js` | `computeGrid()`, `computeAllGrids()`, `tileBackground()`, `croppedBackground()` — чистые функции без DOM |
| `docs/js/game.js` | модуль `Game` (IIFE): рендер поля, управление, ходы, просмотр оригинала, финал |
| `docs/js/app.js` | переключение экранов, галерея, экран сложности, кнопки выхода и новой игры |

## Ключевые решения

### Сетка

`computeGrid(W, H, N)`: `tile = floor(min(W, H) / N)`, по меньшей стороне ровно `N` плиток, по большей — `floor(большая / tile)`. Остаток исходника обрезается симметрично (`offsetX/offsetY`), обрезанная область — `cropWidth × cropHeight`. Проверено на примерах ТЗ: 1000×700 даёт 7×10@100, 7×5@140, 8×6@116.

### Фрагменты на CSS

Картинка не режется. Каждый фрагмент — `<div class="tile">` с общим `background-image` и **только процентными** `background-size` / `background-position`:

- `background-size = (W / tile) × (H / tile)` в процентах от самой плитки;
- `background-position = (x·tile + offsetX) / (W − tile) × 100%` (и так же по Y).

Проценты в `background-position` отсчитываются от «плитка − картинка», поэтому такая формула одновременно даёт нужный сдвиг и учитывает обрезку. Без остатка она сводится к формуле из ТЗ `x / (cols − 1) · 100%`. Фон привязан к фрагменту и при перемешивании не меняется — меняется только порядок в массиве `order`.

Просмотр оригинала и финальная картинка — `.board__original` поверх поля: `background-size = (W / cropWidth) × (H / cropHeight)`, `background-position: 50% 50%` (обрезка центрированная), размер совпадает с полем.

### Состояние поля

`order[позиция] = номер фрагмента`, `tiles[номер фрагмента] = DOM-элемент`. Победа — когда `order[i] === i` для всех `i`. Перемешивание — `N` случайных парных обменов для `N` плиток, с защитой от случайно собранного стартового расклада. Рендер переставляет существующие элементы через `appendChild` (CSS Grid раскладывает их по порядку).

### Адаптив

`.board-area` — `flex: 1; min-height: 0; overflow: hidden`. `Game.fit()` (по `ResizeObserver` + `resize`) считает `scale = min(доступнаяШирина / cropWidth, доступнаяВысота / cropHeight, 1)` и задаёт полю размер в пикселях. Отображаемый размер нигде не зашит: `1` в `min()` запрещает растягивание выше 1:1, а плитки внутри — `1fr` в CSS Grid, поэтому проценты фонов остаются верными на любом размере. Прокрутки нет: `body { overflow: hidden }`.

### Управление

Pointer Events на контейнере поля (делегирование) + `touch-action: none`, HTML5 Drag and Drop не используется. Порог перехода в drag — половина плитки; ниже порога срабатывает клик-клик (`is-selected`), выше — перетаскивание: элемент поднимается `z-index` и следует за курсором через `transform: translate()`, целевая клетка вычисляется из координат относительно поля и подсвечивается (`is-target`). Ход = обмен двух плиток, счётчик в `#moves`.

### Победа

`celebrate()`: класс `is-flashing` на 500 мс (жёлтая анимация тонких линий сетки) и плавное появление панели `#win`; затем `is-assembled` — плитки скрываются, остаётся `.board__original`. Панель победы лежит в потоке под полем, поэтому `ResizeObserver` пересчитывает размер поля и прокрутка не появляется.

### i18n

`RU / EN` в правом верхнем углу. По умолчанию — сохранённый выбор, иначе `navigator.language.includes('ru') ? 'ru' : 'en'`. Статические подписи переводятся через `data-i18n`, динамические (галерея, сложности, ходы, кнопка оригинала) перерисовываются колбэком `onLangChange`. `<title>` всегда «Игра-мозаика» — так требует ТЗ.

### Деплой

GitHub Pages: ветка по умолчанию, папка `/docs`. Все пути относительные, поэтому работает и в подкаталоге репозитория, и локально.

## Договорённости по стилю

Воздушный минимализм: белый фон, тонкие серые линии (`--line`), крупные кнопки-«пилюли» с `min-height` ≥ 42–54 px, размеры и отступы через `clamp()`. Комментарии в коде — на русском, только там, где объясняют неочевидное (математика фонов, порог drag, авто-отступы для центрирования).
