# Задача

Реализовать адаптивную браузерную игру-мозаику (пазл из квадратных фрагментов).

## 1. Стек технологий

- ванильный JavaScript, CSS. Без сборщика и компиляции
- Точка входа — `docs/index.html`. Локальные пути к скриптам и стилям — относительные (`./...`)
- Чистый фронтенд (SPA). База данных и бэкенд **не** требуются

## 3. Интернационализация (i18n)

- В правом верхнем углу экрана должен быть аккуратный переключатель языка: RU / EN.
- По умолчанию язык определяется через navigator.language. Если язык содержит 'ru' — включается RU, иначе — EN.
- Локализовать нужно весь текст: интерфейс выбора сложности, сообщение о победе, кнопку новой игры, заголовки, счётчик ходов, переключатель просмотра оригинала, кнопку выхода.

## 4. Математика деления и адаптивная сетка

- Сетки генерируются автоматически на основе пропорций картинки: по меньшей стороне картинка ВСЕГДА делится на N частей, где N от 5 до 11.
- По большей стороне количество частей рассчитывается автоматически так, чтобы фрагменты оставались строго квадратными. Округляй в меньшую сторону, а лишние пиксели оригинала (остаток) — аккуратно обрезай (центрируй картинку в рамках получившейся общей сетки).

Например, если картинка размером 700 по вертикали и 1000 по горизонтали, то:

- при делении картинки на 7 квадратов по меньшей стороне - должно получиться 7x10 квадратов размером 100x100 пикселей,
- при делении картинки на 5 квадратов по меньшей стороне - должно получиться 5x7 квадратов размеров 140x140 пикселей (лишняя часть картинки обрезается),
- при делении на 6 квадратов по меньшей стороне - должно получиться 6x8 квадратов размеров 116x116 пикселей (лишняя часть картинки обрезается).

- ВАЖНО (Responsive Design): Игровое поле должно вписываться в доступную область экрана компьютера/смартфона (минус шапка, счётчик, кнопки): виден весь пазл, без прокрутки вверх-вниз и влево-вправо. Не используй фиксированные пиксели (px) для отображаемого размера сетки (примеры 100x100 / 140x140 / 116x116 выше — только расчёт нарезки исходника). Если обрезанная картинка в масштабе 1:1 меньше доступной области — не растягивать её.

## 5. Техническая реализация кусочков (CSS)

- Не нарезай картинку физически. Каждый фрагмент мозаики — это HTML-элемент (`<div>`), где картинка установлена через CSS-свойство `background-image`.
- Чтобы в каждом квадрате отображалась только нужная часть, рассчитывай сдвиг через проценты на основе исходных координат (x, y) кусочка в правильной сетке:
  - `background-size` всей сетки = (количество_колонок * 100%) (количество_строк * 100%).
  - `background-position` для кусочка = X: (x / (колонки - 1)) * 100%, Y: (y / (строки - 1)) * 100%. (Если колонка или строка одна, то 0%).
- При перемешивании блоков свойства `background-image`, `background-size` и `background-position` должны оставаться неизменными (привязанными к конкретному кусочку). Меняется только их текущее положение в массиве состояния игрового поля.

## 6. Работа с изображениями

- На главном экране отображается галерея миниатюр этих картинок. Название картинки на выбранном языке: на десктопе — при наведении, на смартфоне — подпись видна под миниатюрой.
- В галерее миниатюры должны быть одинаковой высоты, ширина должна быть по пропорциям картинки. Каждая миниатюра вписывается целиком без обрезки (CSS `object-fit: contain`).
- На экране смартфона картинки должны также отображаться целиком, т.е. если картинка не влезает по ширине, нужно уменьшать масштаб, даже если высота картинки окажется меньше чем у других миниатюр.
- Клик/тап по миниатюре открывает экран выбора сложности (сетки разбиения).

## 7. Игровой процесс и управление

- После выбора сложности фрагменты перемешиваются: N случайных парных обменов для пазла из N плиток.
- Цель игры — восстановить исходное изображение.
- На экранах выбора сложности и игры должна быть кнопка выхода: она сразу возвращает в галерею (не на экран выбора сложности).
- Реализуй два альтернативных способа управления, работающих одновременно:
  1. Клик-клик (или Тап-тап): Клик по одному квадрату визуально выделяет его (аккуратная рамка), клик по второму — меняет их местами.
  2. Drag-and-Drop: Перетаскивание фрагмента на место другого. ВАЖНО: Используй Pointer Events (`pointerdown`, `pointermove`, `pointerup`) вместо HTML5 Drag and Drop API. Это критически важно, чтобы перетаскивание без багов работало и мышкой на ПК, и пальцем (Touch) на мобильных устройствах.
- Порог перетаскивания — половина размера плитки. Движение меньше порога — клик (выделение/обмен), больше порога — drag.
- При перетаскивании плитка должна отображаться над другими плитками и следовать за курсором/пальцем пользователя.
- Ходом считается обмен позиций двух плиток (клик-клик или drag). Нужно подсчитывать количество ходов во время игры и отображать его в процессе. В конце игры также сообщать количество ходов.
- Сделать переключатель просмотра оригинала: в процессе сборки пазла можно показать оригинальную картинку; повторное нажатие возвращает к пазлу.
- Оригинальная картинка должна отображаться в таком же размере, как собираемое изображение, с таким же обрезанием краёв, как у части картинки, используемой для пазла.
- Логика победы: Как только все фрагменты встали на свои исходные правильные позиции, под мозаикой плавно появляется сообщение "У вас получилось!" и кнопка "Начать новую игру" (возвращает на экран выбора картинок), при этом сетка должна мигнуть ярким жёлтым цветом на 500 мс, после чего сетка исчезает и показывается только та же обрезанная картинка, что использовалась для пазла (без сетки), а не полный файл из галереи.

## 8. Дизайн и стили

- Общий стиль: Максимально воздушный, минималистичный, элегантный.
- Чистый белый фон, много свободного пространства.
- Фрагменты мозаики разделены едва заметными тонкими линиями.
- Кнопки крупные, контрастные, с хорошими отступами, чтобы по ним было удобно тапать пальцем на смартфонах.
- В заголовке окна браузера (`<title>`) должно быть прописано: "Игра-мозаика".
